# BionicPRO — Спринт 9. Задание 2: Сервис отчётов

## 1. Описание решения

Реализован сервис формирования отчётов о работе бионических протезов на основе данных CRM и телеметрии.

**Архитектура решения:**

`CRM + Telemetry DB → Apache Airflow → ClickHouse → Reports API → UI`

- **Apache Airflow** — ежедневная загрузка и обработка данных.
- **ClickHouse** — хранение подготовленной аналитической витрины.
- **FastAPI** — предоставление отчётов через REST API.
- **Keycloak + BFF** — аутентификация и проверка доступа.
- **React** — интерфейс для скачивания отчётов в CSV.

Архитектурная диаграмма: `Architecture_C4/BionicPRO_Task2.drawio`.

## 2. Реализованная функциональность

| Требование | Реализация |
|---|---|
| ETL-процесс | Airflow DAG `bionicpro_reports_daily` |
| Запуск по расписанию | Ежедневная обработка данных |
| OLAP-витрина | ClickHouse, таблица `user_prosthesis_reports` |
| Получение отчёта | `GET /reports?from_date=...&to_date=...` |
| Формат отчёта | CSV |
| Авторизация | OAuth 2.0 Authorization Code + PKCE |
| Ограничение доступа | Пользователь получает данные только своих протезов |
| Необработанный период | HTTP 409 |
| Интерфейс | Кнопка скачивания отчёта |

Отчёты формируются из предварительно подготовленной витрины ClickHouse без сложных вычислений во время запроса.

## 3. Запуск проекта

Из корня репозитория:

```bash
docker compose -f Task2/docker-compose.yaml up --build -d
```

После запуска доступны:

| Сервис | Адрес |
|---|---|
| Frontend | http://localhost:3000 |
| Reports API / Swagger | http://localhost:8000/docs |
| Keycloak | http://localhost:8080 |
| Airflow | http://localhost:8081 |
| ClickHouse | http://localhost:8123 |

Для Airflow используется логин `admin`, пароль можно получить из логов контейнера.

## 4. Генерация отчёта

Запустите DAG `bionicpro_reports_daily` через интерфейс Airflow либо командой:

```bash
docker compose -f Task2/docker-compose.yaml exec airflow \
  airflow dags trigger bionicpro_reports_daily \
  --conf '{"report_date": "2026-10-17"}'
```

Дата должна соответствовать дню, за который в демонстрационном источнике есть телеметрия.

После успешного завершения задач `load_daily_mart` и `mark_day_complete`:

1. Откройте http://localhost:3000.
2. Войдите под тестовым пользователем `user1` с паролем `demo-user1-only`.
3. Выберите обработанную дату.
4. Скачайте CSV-отчёт.

В отчёте должны присутствовать только протезы `p-100` и `p-101`. Данные протеза `p-200` принадлежат другому пользователю.

## 5. Проверка безопасности

Реализованы следующие проверки:

- Без авторизации API возвращает **401**.
- При запросе чужого протеза возвращает **403**.
- При запросе необработанного периода возвращает **409**.
- При некорректном диапазоне дат возвращает **422**.
- Идентификатор пользователя определяется из серверной сессии, а не из параметров запроса.

Запуск тестов:

```bash
docker compose -f Task2/docker-compose.yaml exec reports_api \
  python -m pytest -q
```
